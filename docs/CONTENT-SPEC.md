# 课程内容写作规范（Python Academy · 深度扩充版 v2）

> 本文件是所有阶段课程文件的**唯一写作标准**。写任何一个 `sN.ts` 之前必须完整阅读。
> 范本：`src/data/courses/s1.ts`（第一阶段 8 课，已通过语法与内容校验）。**先读范本，再动笔。**

## 0. 读者画像

- 完全零基础，不认识「变量」「函数」这些词。
- 主要用 iPhone 学习，实战部分用 Windows。
- 会照抄代码，但**不会读报错、不会自己找 bug**。
- 目标：学完能独立写出有实际用途的小程序。

所以每一课都要假设读者「第一次见到这个概念」，术语必须翻译成大白话，代码必须能跑、能对照输出。

## 1. 文件结构模板

```ts
import type { Lesson } from '../../types'

/**
 * 第 N 阶段：阶段名（X 课）
 */
export const stageXLessons: Lesson[] = [
  {
    id: 'sX-01',
    stageId: X,
    order: 1,
    title: '',
    subtitle: '',
    hook: '',            // 生活化的问题，1-2 句，结尾带问号
    objectives: [],      // 3-4 条，可观测的行为动词（能说出/能写出/能判断/能修好）
    analogy: '',         // 大白话比喻，2-4 句
    terms: [],           // 3-5 条 { term, plain }
    content: ``,         // Markdown 正文，见第 2 节
    examples: [],        // 1-2 个，见第 3 节
    compare: [],         // 1-2 条易混淆对比（强烈建议写）
    visual: {},          // 可选：变量变化/循环执行/函数调用可视化
    pitfalls: [],        // 4-5 条常见错误
    keyPoints: [],       // 4-5 条本课小结
    sources: [],         // 来源教材章节
    prerequisites: [],   // 前置课程 id
    task: '',            // 课后动手任务，具体可执行
    exercises: [],       // 5 道，见第 4 节
    minutes: 15,         // 12-20

  },

```

## 2. content 写作规范

**硬规则：content 内绝对不使用反引号（` 和三个反引号的代码块）。**
原因：content 是模板字符串，反引号会截断字符串。所有可运行代码一律放进 `examples`，正文用表格或文字描述语法。

章节骨架（按顺序，标题可微调但必须齐全）：

```
## 一、为什么需要它（知识背景）
   —— 先说清"没有它会怎样"，用生活场景或具体痛点引出

## 二、概念解释
   —— 定义 + 大白话 + 一个贴切比喻

## 三、语法与使用规则
   —— 必须用 Markdown 表格列出：写法 / 说明 / 示例
   —— 讲清必须遵守的规则（成对、缩进、顺序…）

## 四、逐步演示（分步骤）
   —— 用"第一步…第二步…"写出可照做的操作顺序
   —— 指出每一步该观察什么

## 五、常见错误与解决办法
   —— 用表格：现象 / 原因 / 解决
```

可按需增加小节（如「进阶用法」「什么时候别用它」「和其他概念的对比」），但**不得缩减**上述五节。

其他要求：
- 每课 content 正文**不少于 1200 个中文字符**（不含代码），一般 1300-2200 字。
- 正文里可以用 `**加粗**`、表格、有序/无序列表。
- 不要写"如上所述""众所周知"这类空话；每句话都要有信息量。
- 不要大段照抄教材原文，用自己的话重写。

## 3. examples 规范

每个示例必须写全这些字段：

| 字段 | 要求 |
| --- | --- |
| `title` | 一句话说明这段代码干什么 |
| `intro` | 为什么看这个例子，1-2 句 |
| `code` | 真实可运行，带必要注释；**只用英文半角标点** |
| `expectedOutput` | **必须实际运行验证过的输出**，逐字一致（含空格） |
| `lines` | 逐行解析，3-6 条，每条 `{ code, explain }`，code 用该行的精简写法 |
| `trace` | 程序运行过程表格，3-5 行 `{ step, state }`，state 写"此刻变量/内存里是什么" |
| `tryIt` | 让读者动手改动的一句话任务（可选但强烈建议） |

**输出必须实测**：写完每个示例后，用 `python` 实际跑一遍代码，把真实输出复制进 `expectedOutput`。
注意 print 用逗号分隔时会自动补空格，例如 `print("合计", 85)` 输出 `合计 85`（中间一个空格）。

禁止事项：
- 不使用 `input()`（浏览器实验室不支持），练交互就用"预设变量值"模拟。
- 不写需要第三方库才能跑的代码，除非本课 env 明确是 local，并在正文给出安装命令。
- 不写需要网络请求的代码（除网络课，且必须用真实可用接口）。

## 4. exercises 规范

**每课 5 道，题号 `sX-NN-q1` 到 `sX-NN-q5`，难度递增，题型固定分布：**

| 题号 | 题型 | 考什么 |
| --- | --- | --- |
| q1 | `single` 或 `boolean` | 概念理解 |
| q2 | `single` / `boolean` / `blank` | 语法细节（关键符号、规则） |
| q3 | `predict` | 代码阅读：给出代码，问输出（用 keywords 判分） |
| q4 | `blank` 或 `code-complete` | 补全代码 / 填关键符号 |
| q5 | `program` | 编程实践：真正写代码，用测试用例判分 |

### 各题型字段要求

- `single`：`options` 四个选项，格式 `'A. xxx'`，`answer` 写字母如 `'B'`。
- `multiple`：`answer` 是字母数组如 `['A','C']`（少用，最多 1 道）。
- `boolean`：`answer` 写 `'对'` 或 `'错'`。
- `blank`：`answer` 写标准答案，`accepted` 列出可接受变体（含无标点、简称、全角形式）。
- `predict` / `code-complete` / `debug`：**不写 `answer`**，写 `keywords: string[][]`（每组是同义词数组，命中 70% 判对），并可给 `code` 字段展示被分析的代码。
- `program`：`answer: ''`，必须写 `testCases: [{ stdin: '', expected: '精确输出' }]`，`expected` 必须实测过。

### explanation 统一四段式（必须写，且要有信息量）

```
答案：xxx。
思路：为什么是这个答案，考的是哪个知识点。
逐步演示：一步一步走完，让小白能照着复现。
易错提醒：最常见的错误做法是什么，为什么错。
```
每道题的 explanation **不少于 80 字**，program 题的 explanation 必须包含**完整参考答案代码**。

### 其他硬要求

- `stem` 里如果引用代码或术语，用中文引号「」或『』，**严禁在字符串内出现未转义的半角双引号 `"`**。
- 题干自包含：不出现"如上文代码所示"这种依赖外部内容的说法。
- program 题的 stem 必须写清"输出什么、几行、格式"，让读者不用猜。

## 5. 其他字段

- `sources`：标注教材章节，格式 `{ book: 'pcc3' | 'abs3' | 'both' | 'update', chapter: '第N章 xxx' }`。
- `prerequisites`：前置课程 id 数组，必须是本阶段之前的课（如 `['s2-01']`）。
- `visual`：只在"变量怎么变""循环怎么跑""函数怎么调用"这类最需要图解的课写，`kind` 取 `variable`/`loop`/`function`/`flow`。
- `env`：浏览器能完整跑就写 `'browser'`；需要本地文件/第三方库/网络就写 `'local'`，并在 content 开头明确写「这一课在 Windows + VS Code 本地环境完成」及原因。
- `minutes`：12-20，按内容量估。

## 6. 交付前自检（必做）

1. 语法：`node -e "require('esbuild').transformSync(require('fs').readFileSync('<file>','utf8'),{loader:'ts'})"` 无报错。
2. 数量：`grep -c "id: 'sX-"` 等于本阶段课数；`grep -c "qtype:"` 等于课数 × 5。
3. 输出：逐个示例用 `python` 实跑，确认 `expectedOutput` 逐字一致。
4. 索引：每课 `order` 从 1 连续递增，`stageId` 一致，`id` 格式统一。
5. 无占位文字：不出现 Lorem、TODO、待补充、示例文本。
